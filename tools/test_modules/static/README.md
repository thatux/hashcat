# Static test inputs

A mode's "static" input is a prebuilt container checked into the tree, run through the mode's `*2hashcat.py` extractor to get the hash and then cracked. These are the container families: TrueCrypt (`tools/tc_tests/`), VeraCrypt (`tools/vc_tests/`), CryptoLoop (`tools/cl_tests/`) and LUKS (`tools/luks_tests/`, `tools/luks2_tests/`).

Unlike the synthetic oracles, which are one file per mode under `synthetic/`, the container families are deliberately not given a file per mode here. Each family is one compact function in `tools/test.py` (`container_truecrypt`, `container_veracrypt`, `container_cryptoloop`, `container_luks1`/`container_luks2`/`container_luks_legacy`) that derives its hash and cipher from the mode number through small digit tables (`TC_HASH_DIGIT`, `CL_HASH_DIGIT`, ...), and `run_container_mode` dispatches to it by family. A descriptor file per mode would restate that derivation about 130 times for no change in behaviour, which is more code and no clearer, so the static kind is those functions plus the `*_tests/` container dirs rather than per-mode files. The extractors themselves are smoke-tested by `tools/test_2hashcat.py`. See the Implementation progress section of `plan_refactor_testpy.md` for the full rationale.
