# Static test inputs

A mode's "static" input is a prebuilt container, run through the mode's `*2hashcat.py` extractor to get the hash and then cracked. The container artifacts live in subdirectories here: the container families TrueCrypt (`tc_tests/`), VeraCrypt (`vc_tests/`), CryptoLoop (`cl_tests/`) and LUKS (`luks_tests/`, `luks2_tests/`, which are too large to check in and are fetched at test time, so they are gitignored), plus the smaller archive and wallet fixtures each `*2hashcat.py` extractor is tested against end to end by `tools/test_2hashcat.py` (`gpg-ocb-aes/`, `keepass/`, `gitea/`, `rar3/`, `mozilla/`, `metamask/`).

Two more subdirectories, `gpg_tests/` and `pdf_tests/`, are reference fixtures for the GPG and PDF modes (sample keys and documents, with a script to regenerate the GPG data). They are not wired into test.py today, which tests those modes through their oracle and `-g` generation, so they are kept here as the material a static fixture for those modes would be built from.

Each container mode declares this with a one-line `TEST_INPUT = {"kind": "static", "family": ...}` descriptor in `mNNNNN.py` here. test.py reads these without importing (as it reads the profiles) and derives `CONTAINER_MODES`, `TC_MODES`, `VC_MODES` and `CL_MODES` from them, so a mode's kind lives in a file next to the mode rather than in a hardcoded set. `run_container_mode` dispatches to the family's handler by the descriptor's `family`. The per-family hash and cipher parameters stay in test.py (the digit maps, the cascades, `LUKS1_HASH_CIPHER`), since they are derivation data the descriptor does not carry.
